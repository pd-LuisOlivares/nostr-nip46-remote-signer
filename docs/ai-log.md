# Registro de interacciones con IA

Índice de trazabilidad de las interacciones con agentes de IA que intervienen en este proyecto. Las reglas que lo rigen están en `AGENTS.md` §9. Las transcripciones están en [`docs/ai-sessions/`](ai-sessions/).

## Convenciones

- **Fechas:** UTC (hora de los registros de sesión). Chile continental en noviembre usa UTC-3.
- **Agente y modelo:** solo se consignan cuando constan en los metadatos de la sesión; si no, "no disponible".
- **Nivel de razonamiento:** el valor `effort` que aparece en los metadatos de la sesión de Claude Code. No se ha verificado de forma independiente.
- **Estado de la transcripción:** `Completa`, `Parcial` o `NO RECUPERADA`. Una transcripción nunca se reconstruye de memoria.
- **Entradas por agente:** los prompts preparados con ChatGPT se registran como ChatGPT y no se atribuyen a Claude Code (ver "Interacciones no recuperadas").

## Criterio para distinguir decisión, asistencia e implementación

Este registro separa tres tipos de contenido. Sirve para que la evidencia de uso de IA muestre quién decidió, quién asesoró y quién ejecutó.

| Categoría | Qué incluye | Quién |
|---|---|---|
| **Decisión humana** | Selección, aprobación o rechazo de alternativas; autorizaciones; definición de alcance y prioridades. | Una persona (el propietario del proyecto). |
| **Asistencia de IA** | Análisis, recomendaciones, identificación de riesgos y propuestas. | Un agente de IA. Una propuesta **no** es una decisión mientras una persona no la apruebe. |
| **Implementación por agentes** | Archivos creados, código modificado, pruebas ejecutadas y sus resultados. | El agente que lo realizó (Claude Code, Codex u otro), nombrado en la entrada. |

Reglas de uso:
- **No se atribuyen decisiones al propietario por defecto.** Se le atribuye una decisión solo si hay una instrucción, aprobación o rechazo suyos en la transcripción. Si una propuesta de la IA quedó sin aprobación expresa, se registra como propuesta pendiente.
- **No se atribuye trabajo de implementación a una persona** si lo realizó un agente de IA. Cuando una persona ejecuta algo (por ejemplo, configurar la identidad de Git), se indica como acción humana.
- Un mismo hecho puede tener varias partes: p. ej. una persona decide, la IA propone la redacción y un agente la implementa.
- Las acciones de verificación (pruebas, `git diff --check`, escaneos) cuentan como implementación del agente que las ejecutó y deben indicar su resultado real.

## Procedimiento de exportación y verificación (vigente desde 2026-11-22)

**Criterio (decisión del propietario, 2026-11-22; sustituye el de «exportar solo al cierre de cada fase»).** Las transcripciones se exportan **al cierre de cada Paso o bloque de trabajo autorizado**, y además se **verifican antes de cada commit y antes de la publicación final**. Cada interacción se registra en este índice en el momento en que se completa, no se difiere.

**Comandos explícitos y reproducibles** (no hay hooks de Git: el propietario **no** los autorizó). Los historiales viven fuera del repositorio, en la carpeta de datos de usuario de Claude Code; `<historial>` es esa carpeta del proyecto:

```powershell
python tools/ai_sessions.py check  --history-dir <historial>     # ¿falta algo? código 1 si hay pendientes (transcripciones, interacciones nuevas o índice)
python tools/ai_sessions.py export --history-dir <historial> --redact-user <usuario-local> --redact-name "<nombre del autor>"   # genera lo que falta (los datos personales se pasan por argumento: no se versionan)
python tools/ai_sessions.py scan   docs/ai-sessions docs/ai-log.md --blocking-only            # escaneo de patrones sensibles
python tools/ai_sessions.py backup --history-dir <historial> --dest <carpeta-privada-fuera-del-repositorio>
```

- **Manifiesto:** cada interacción nueva se añade a `tools/ai_sessions_manifest.json` con la marca de hora (UTC) del prompt del propietario que la inicia; llega hasta el inicio de la siguiente, según el orden del archivo de sesión. Una interacción es un bloque de trabajo autorizado por el propietario.
- **Estados:** `COMPLETA` si la sesión de origen está cerrada; `PARCIAL` mientras siga abierta (su último registro es reciente). Una transcripción **completa** nunca se sobrescribe con contenido distinto; una **parcial** se actualiza al reexportar. El extractor es idempotente: con el mismo historial genera los mismos bytes.
- **Seguridad:** nunca se copian los JSONL al repositorio ni se incluyen resultados de herramientas. Se redactan claves privadas, URI `bunker://`, secretos de conexión, JWT, tokens, contraseñas, hashes de contraseña, correos, rutas locales, usuario local y nombre del autor. Las cadenas hexadecimales de 64 caracteres se clasifican por contexto (se conservan claves **públicas**, identificadores y huellas SHA-256) y **la exportación del archivo afectado se detiene ante cualquier duda**; solo una revisión humana la libera (`--allow-hex-prefix`). Antes de dar un archivo por seguro: escaneo automático y revisión directa.
- **Respaldo:** los JSONL originales se copian a una carpeta privada **fuera del repositorio**, solo accesible por el usuario, que no está bajo Git ni bajo una carpeta de sincronización; si no se puede garantizar, el comando se bloquea y no copia nada. No se eliminan ni sobrescriben los originales.
- **Pruebas:** `tests/test_ai_traceability.py` comprueba la correspondencia archivos ↔ índice, la existencia de los enlaces, la ausencia de patrones sensibles, la detección de interacciones nuevas sin exportar, la clasificación completa/parcial y la idempotencia.
